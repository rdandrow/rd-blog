# rd-blog

A multi-author blog. Laravel 12 (PHP 8.4 in CI) · Inertia 2 · Vue 3 + TypeScript ·
Tailwind v4 · shadcn-vue (reka-ui) · Fortify (auth, mandatory 2FA) · PostgreSQL 16 ·
Pest 4 + Vitest 4.

**Current work is the cleanup in `docs/ROADMAP.md`.** Read it before starting anything.
It lists every known issue and which phase fixes it.

## Skills: load before acting

- `work-step`: any roadmap item, bug fix, or feature. Covers branch → baseline →
  test-first → verify → review → PR.
- `review-tests`: before trusting, rewriting, or deleting existing tests, and after
  `/code-review` on any branch that changes tests.
- `run-locally`: Postgres, the dev server, and running the app or test suites.

## Commands

```sh
composer test            # Pest, parallel (needs local Postgres; see run-locally)
composer test:sequential # Pest without --parallel, for debugging
npm run test:run         # Vitest (tests/frontend), once
npm run types            # vue-tsc --noEmit; `vite build` does NOT type-check
npm run lint:check       # ESLint, check-only (`npm run lint` auto-fixes)
npm run format:check     # Prettier on resources/ (`npm run format` writes)
vendor/bin/pint --test   # PHP style, check-only (`vendor/bin/pint` writes)
npm run build            # production assets
composer dev             # server + queue + logs + vite
```

CI runs all of the check-only commands plus both test suites. Run them before every
commit, and don't commit a red suite.

## Where things live

- Routes: `routes/web.php` (public, admin, social) and `routes/settings.php`.
- Roles: `users.role` is `master_admin`, `admin`, or `member`. The checks are
  `User::isMasterAdmin()` / `isAdmin()` / `isRegularAdmin()` / `isMember()` and the
  `admin` / `master.admin` / `ensure.2fa` middleware.
- Authorization: `app/Policies`, called from FormRequest `authorize()` or
  `$this->authorize()`. Middleware is not a substitute for a policy.
- Business logic: `app/Services` (`BlogPostService`, `DashboardMetricsService`, ...).
  Controllers stay thin.
- Caching: `app/Services/Concerns/CachesBlogData.php` uses versioned keys that
  `BlogPost::invalidateBlogCache()` bumps on save and delete.
- Frontend: pages in `resources/js/pages`, shared types in
  `resources/js/types/index.d.ts` (keep them in sync with what the server sends,
  especially `HandleInertiaRequests::share`), and generated shadcn components in
  `resources/js/components/ui` (excluded from ESLint; don't hand-edit them).
- `resources/js/actions`, `resources/js/routes`, and `resources/js/wayfinder` are
  generated by Wayfinder and gitignored.

## Rules

- **Test-first.** For any behavior change, write the test, run it, see it fail for the
  right reason, then implement. Bug fixes start with a test that reproduces the bug.
  Styling and copy don't need tests first.
- **Existing tests were written after the code.** A passing test may lock in a bug
  (for example, `BlogPostPolicyTest` asserts that any user can create posts). When
  the intended behavior is unclear, ask; don't assume the test is right.
- **Authorization belongs in policies.** Every admin and owner action needs a policy
  check, even when middleware already guards the route.
- **Requests that change state are never GETs.**
- **No new infrastructure without a stated need**: indexes, caching layers,
  monitoring, batch helpers, and docs included. The roadmap's Phase 2 exists because
  this happened before. Ask first.
- Never edit a migration that has already shipped. Add a new one.
- One branch per roadmap item, merged through a PR into `develop`. Never commit to
  `develop` or `main` directly. Push and open PRs only when asked.
- Formatting-only commits go in `.git-blame-ignore-revs`.
- **Leave no running state behind.** When you finish, stop any Postgres server, dev
  server, or Vite process you started, and drop the parallel test databases. See
  `run-locally`. Never use `brew services start`, which launches the server at login.
- Versions here are newer than most training data. Check the official Laravel,
  Inertia, Fortify, Pest, and Vitest docs rather than relying on memory.
